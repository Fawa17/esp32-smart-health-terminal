# 智能健康监护终端（ESP32-S3）

给独居老人用的健康监测终端：采心率血氧、体温、步数与跌倒，本地触摸屏显示，数据经 MQTT 上云，支持网页改阈值和远程升级。

> 固件 1.23 MB（2 MB 应用分区余 41%）｜ESP-IDF v5.5.5｜FreeRTOS 双核｜LVGL 9.6｜已实机验证

## 这是什么

项目最早是一套 STM32F103 上的东西：STM32 负责采传感器和驱动 OLED，旁边再挂一块 ESP8266，靠串口发 AT 指令连服务器。两块芯片、两套代码，改一个字段要动两个工程。

2026 年整体搬到 ESP32-S3 上，变成单芯片：AT 指令层整个删掉换成 esp-mqtt 直连；128×64 的 OLED 换成 240×296 电容触摸屏并上 LVGL；顺带把双分区 OTA、崩溃现场记录、传感器掉线自恢复这些工程上的东西补齐。

现在这条链是通的：采数据 → 跑算法 → 屏幕显示 → MQTT 上报 → 网页看数和改阈值 → 需要时远程升级。

## 界面

四页，左右滑动切换，底部标签栏可直点：

| 页面 | 内容 |
|---|---|
| 时钟页（起始页） | 48 px 大字时间、日期与星期、联网状态点 |
| 数据页 | 心率 / 血氧 / 体温 / 步数四张卡片，底部状态条显示正常、掉线或跌倒 |
| 设置页 | 心率上限、血氧下限、体温上限的 ± 调节，固件版本与「开始升级」按钮 |
| 告警页 | 最近 5 条告警记录；触发告警时全屏红色弹窗，需手动确认 |

## 现在能做什么

- **心率、血氧**：MAX30102，100 sps，攒满 200 点算一次。算法基于 Maxim AN6409，参考实现有几处问题，改了 7 个地方（其中 AC/DC 分量下标错用会让血氧系统性偏低）。
- **步数、跌倒**：MPU6050。步数用重力低通加动态阈值；跌倒按失重、冲击、静止三段判，避免拍桌子就报警。
- **体温**：NTC 分压，Beta 公式，用芯片 eFuse 中的出厂校准值，另留可调偏移用于标定。
- **时间**：DS1302 + SNTP 校时，时间每 5 分钟往 NVS 存一份，断电重启不会退回 2000 年。
- **界面**：LVGL 四页，手势翻页，按键息屏 / 唤醒，告警弹窗。
- **云端**：MQTT 上下行、网页改阈值、OTA 版本查询。
- **升级**：双分区 OTA，新固件启动后 60 秒内连不上服务器就自动回滚。
- **可靠性**：看门狗按槽位心跳、器件掉线检测与故障上报、panic 现场写 flash。

## 硬件与接线

| 器件 | 接口 | 引脚 |
|---|---|---|
| 显示屏 TK0134 240×296 IPS | SPI | SCLK=GPIO12，MOSI=GPIO11，CS=GPIO10，DC=GPIO13（模块未引 RST 与 BL） |
| 触摸 CST816S（0x15） | I2C | 共用总线 |
| MPU6050（0x68） | I2C | 共用总线 |
| MAX30102（0x57） | I2C | INT=GPIO21 |
| NTC 温度模块（AO） | ADC | GPIO4（ADC1_CH3） |
| DS1302 | 三线 | CLK=GPIO5，DAT=GPIO6，RST=GPIO7 |
| 按键 | GPIO | GPIO14 接 GND，息屏 / 唤醒 |
| I2C 总线 | 400 kHz | SDA=GPIO8，SCL=GPIO9 |

屏幕是 8 针的「SPI 显示 + I2C 触摸」二合一模块。排针上同时印着 `SDA` 和 `MOSI`，是两个完全不同的信号：`CS/DC/SCK/MOSI` 走显示，`SCL/SDA` 走触摸。第一次接线就是把这两组搞混了，表现为 I2C 扫描什么都扫不到。

## 代码怎么分层

按感知、系统、业务、网络四层拆，共 16 个自研组件、43 个源文件、约 1.6 万行：

```
业务层   ui_lvgl（界面）        net_app（物模型 + OTA 协调）
网络层   wifi_mgr  mqtt_cli  ota_app
系统层   watchdog  sys_pm  time_keeper  crash_log  app_data
感知层   mpu6050  max30102  ntc_temp  ds1302  display  touch  hr_algo
基础层   bsp_i2c（总线、互斥量、9 脉冲解锁）
```

层与层之间尽量不直接引用，用回调接：`sys_pm` 不认识屏幕和触摸，只提供 `sys_pm_hooks_t` 让 `main.c` 去接；`net_app` 不认识 DS1302，校时通过 `net_time_cb_t` 回调传出去；所有业务任务只往 `app_data` 写快照，不碰 LVGL。

直接好处：写界面时不用管数据从哪来，换传感器时不用动界面。

## 快速开始

前置：ESP-IDF v5.5.x（`idf.py --version` 确认）、一块 16 MB Flash 的 ESP32-S3 板。

```bash
idf.py set-target esp32s3
idf.py menuconfig      # Network (WiFi + MQTT) 里填 WiFi 与 Broker
idf.py build flash monitor
```

第一次 `build` 时组件管理器会从 components.espressif.com 拉 LVGL，需要联网。

启动后串口大致是这样：

```
I (312) app: ===== 模式：全部运行 =====
I (1158) ds1302: 初始化完成 CLK=5 DAT=6 RST=7
I (1203) mpu6050: WHO_AM_I=0x68，初始化完成
I (2325) wifi: STA 启动，开始连接
I (5374) ota: 运行分区 ota_0，固件 v1.5.3，状态 VALID
I (5401) mqtt: MQTT 已连接
```

## 分区表

16 MB Flash：

| 分区 | 偏移 | 大小 |
|---|---|---|
| nvs / phy-init | 0x9000 / 0xf000 | 24 KB / 4 KB |
| otadata | 0x10000 | 8 KB |
| ota_0 / ota_1 | 0x20000 / 0x220000 | 2 MB × 2 |
| coredump | 0x420000 | 64 KB |
| storage / vfs | 0x430000 / 0x830000 | 4 MB / 8128 KB |

app 分区必须 64 KB 对齐，否则构建直接报 `Partition ota_0 invalid: Offset 0x12000 is not aligned to 0x10000`。

## 资源占用

- Flash：1 231 632 B（应用分区 2 MB，余 41%）
- 内部 RAM：静态占用约 45%（帧缓冲、LVGL 堆在 PSRAM）
- 刷屏：整帧 141 KB / 28 ms（40 MHz SPI 上限约 35 fps）
- I2C：三路器件共享 400 kHz 总线，批量取样后抢锁 165 次/秒

## 几个卡了很久的问题

**屏幕整片像负片**

标称 ST7789，按 ST7789 初始化后颜色全反：黑底变白、深蓝变浅绿，字也糊。调反色开关、BGR 顺序、字节序，全没用。找卖家要资料才发现驱动 IC 其实是 **TK0134**：ST7789 的 `0xB0` 是伽马寄存器，TK0134 的 `0xB0` 是显存访问控制寄存器，官方序列把显存读写方式写坏了，所以怎么调颜色都不对。最后丢掉官方 panel 驱动，按 datasheet 只发 6 条命令自建初始化与刷屏时序。

**OTA 升到一半板子自己重启**

每次升到三分之一左右就重启，日志里看门狗报「采样任务卡死」。根因是 `esp_ota_write` 每擦一个 4 KB 扇区要几十毫秒，期间两个核的 cache 全关、I2C 中断被推迟，1.6 MB 需擦 389 次，采样任务连续几秒轮不到 CPU。加升级期看门狗豁免后一次升完。

**FIFO 写指针永远是 0**

驱动按「读指针不等于写指针才读」判断，结果一个样本都取不到。这颗芯片的 `WR_PTR` / `RD_PTR` 恒读回 0，但 `OVF_COUNTER` 在涨，说明它一直在产样本。改成「检测到溢出且尚未取到样本就切盲读模式」，直接按固定节拍读 FIFO，数据恢复正常。

## 已知问题

- **DS1302 模块不稳定**：三次自检互相矛盾（RAM 回环读回 `0x4B` / `0x00`，秒值 `0x13` 倒退成 `0x10`），改时序、改位序、加两组自校准都无效，判断为假片。时间功能已改为 SNTP + NVS 兜底，DS1302 有就用、没有不影响。
- **心率血氧未标定**：手上没有指夹血氧仪，只做了自洽性检查（同状态下读数标准差 1 bpm 以内），绝对精度待补。
- **触摸 IRQ 未引到排针**：只能 40 Hz 轮询。
- **MQTT 走明文 1883**：未启 TLS。
